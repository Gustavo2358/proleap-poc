# Engenharia

Esta área reúne políticas reutilizáveis para alterar e avaliar o projeto sem duplicar os contratos de cada subsistema.

Serão criados conforme a migração extrair conteúdo validado:

- `semantic-analysis-policy.md`: semântica antes de exemplos, comportamento conservador, incerteza explícita e respeito às fases de análise.
- `semantic-testing.md`: classes de equivalência, casos adversariais, propriedades, metamorfismo e oráculos independentes.
- `performance-policy.md`: preservar a semântica ao otimizar e verificar a forma algorítmica sem thresholds frágeis de máquina.
- `observability-policy.md`: logging, diagnósticos, cardinalidade e lifecycle.
- `work-item-protocol.md`: será criado na Fase 9 para trabalho ativo pequeno e roteável.

Use esta família para método de engenharia. Para saber o comportamento atual de normalização, AST ou resolução, navegue para `../domain/`.
