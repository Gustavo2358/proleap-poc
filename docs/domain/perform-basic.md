# CP6 PERFORM BASIC — SP 1.8.0

BASIC_PROCEDURE_PERFORM publishes each proved local paragraph activation with an
intrinsic MOVE body and a continuation specific to that callsite. Any finite number
of distinct targets or repeated activations is permitted. No control.local is used.

Authority: IBM Enterprise COBOL 6.4, Basic PERFORM, printed pp. 413–414,
[official Language Reference](https://publibfp.dhe.ibm.com/epubs/pdf/igy6lr40.pdf).
The paragraph executes once and returns after its final statement to the next
statement after that PERFORM. Ordinary paragraph entry has a different completion.

PerformSemantics consumes canonical entry, paragraph/sentence membership, typed
PERFORM controls, normal continuations and the resolved PERFORM_FROM candidate.
The primary paragraph has a closed supported path ending in GOBACK; a target is a
distinct local paragraph with a nonempty linear supported MOVE body. Arbitrary
extra paragraphs and BASIC activations are not cardinality errors. Main membership
and target proof are indexed/cached, without repeated full-primary scans per callsite.
An unproved isolation, recursive/control body, section target, THRU, TIMES, UNTIL
or VARYING remains a local gap. Its statement and program remain published.

Each PerformFact carries target identity and origins, targetEntry, ordered body,
targetExit and callsite normalContinuation. The last target MOVE has NONE intrinsic
continuation. The lower specializes labels/operations/operands by activation:
Jump(body@site), ordinary MOVE transfers, Jump(resume@site). Memory identities stay
shared. This normalization preserves BASIC behavior without conflating return
contexts. No external program dependency is generated by PERFORM itself.

SP1.8 does not repeat primaryStatements in every activation wire record. The shared
explicit entry/continuation graph supplies primary structure. This avoids quadratic
wire growth for repeated small targets. Physical array order has no control meaning.
IndependentStorageSet remains source-derived, with no new storage assumptions.

Legacy SP1.6/1.7 use SIMPLE_SINGLE_CALLSITE_PROCEDURE_PERFORM and a body exit tied
to its unique resume, with a per-activation primary inventory. Those old wire
semantics remain explicit in the decoder; they are not silently reinterpreted.

CompositionalityContractTest covers 1/2/5/40 occurrences and a 20-CALL/10-IF/5-PERFORM
mixture. PartialProgramFactsTest includes distinct and repeated target callsites.
PerformBasicTest retains literal/copy/overwrite, provenance and isolation negatives.
See the [permanent composition policy](../architecture/compositional-partial-lowering.md).

An unqualified PERFORM is an observed control region with unavailable continuation.
Its syntactic resume alone cannot exclude execution of body CALL sites. The
`control-body` regression protects this boundary without adding precise CALL bodies
or general PERFORM semantics. Observed DISPLAY with exception handlers likewise
retains open control; only handler-free DISPLAY publishes a sole normal successor.
