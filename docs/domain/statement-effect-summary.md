# RF-W2 — typed effect summaries

IN_PROGRESS. SP 2.17 adds `statementEffects`: each summary names one observed statement and existing operand IDs. An absent summary means effects are unknown. An empty inventory means no summaries were proved, never an effect-free program. Storage remains 1.5; no AIR normative extension is needed because memory envelopes already distinguish known reads/writes, other bounds and mustOverwrite.

The shared frontend `StatementEffectSummary` is produced from typed grammar contexts and existing AST operands. Mutation inventory and SP projection consume the same fact. It does not calculate values or control flow. Existing continuation proof, input gaps and statement provenance remain independent dimensions.

First proof: DISPLAY_SIMPLE. IBM Enterprise COBOL 6.4 defines [DISPLAY](https://www.ibm.com/docs/en/cobol-zos/6.4.0?topic=statements-display-statement) as transferring sending operands to an output device. For literals and structurally simple data references, the typed adapter records reads, no storage writes/exposure and an output/environment effect. It preserves observed coverage and open control/environment semantics. It does not treat DISPLAY as NOP. Functions, special registers, subscripts, ref-mod, AT, UPON and handlers stay outside this proof. This narrower boundary is deliberate; an omitted summary retains the conservative fallback.

Summary version 1.0.0: knownReads/mayWrites/mustOverwrite/exposedRegions reference canonical operands. unknownReadBound/unknownWriteBound/unknownExposureBound are NONE (complete dimension) or ALL (open). MUST is a subset of writes, never inferred merely from knowing an address. Environment and value-transform knowledge are distinct. The summary's owning statement supplies provenance; its typed proof records the semantic rule. Materialization failure reopens the affected bound. No source scan or nominal disjunction proof is introduced.

The adapter traverses each operand once; summary lists and sets are linear in the statement footprint. Physical addresses reuse existing allocation/view/alias proofs. Preliminary tests freeze literal/read DISPLAY and reject extended/unknown forms. Later focal adapters will distinguish whole overwrites from MAY writes, particularly handlers and partial group initialization. [INITIALIZE](https://www.ibm.com/docs/en/cobol-zos/6.4.0?topic=statements-initialize-statement) selects elementary receiving items, so a known group address alone never proves a whole-group MUST overwrite.
